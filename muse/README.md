# Muse Pebble plugin

*Uses the Muse app's private web API and session, reverse engineered.*

Index agent destination (see `agent` in CoreApp's `test-apps/plugins.md`). Settings open native
Muse sign-in, capture the account session, and list writable active chats. New accounts default
to **Main chat**. The destination persists for the same account; switching accounts resets it to
Main chat. A missing/archived chat fails instead of sending elsewhere. The action returns an
acceptance receipt, not the assistant's answer.

## Functions

### `send_to_agent(message, chat_id?)`

Send a message to one of the user's Muse chats. chat_id is an instanceId from agent/chats or a chat name; omit it to use the chat selected in plugin settings (Main chat by default). Do not use unless the user explicitly addresses Muse or asks to send something to it, e.g. "message Muse …", "send to Muse …", "tell Muse …", "ask Muse …" or "Muse, …". Never use it for notes, reminders, or messages meant for anyone else. Returns a delivery receipt, not Muse’s answer. Do not automatically retry an uncertain delivery.

- `message` (string): The text to deliver to Muse, without the "send to Muse" instruction itself.
- `chat_id` (string, optional): an `agent/chats` instanceId, or a chat name ("Main chat" for the
  main chat). Exact names take priority over partial matches; ambiguous or unknown names fail
  without sending.

### Sources

- `agent/chats`: `main` (Main chat) plus each writable active side chat; `instanceId` is the Muse
  session id and `name` its title. A cached list under 5 minutes old is returned at once;
  otherwise the read lists chats on its own connection, outside the queue sends and settings
  share, and falls back to the stale list (or just Main chat) if that fails. The list (chat
  titles only) is cached best-effort in `localStorage`, apart from the credential, and updated
  whenever chats are listed; a list is kept only if the sign-in it was fetched with is still
  the saved one and nothing newer is cached.
- `agent/configured`: true once signed in (the settings destination, Main chat by default, is
  always set). `name` is the selected chat's title. Read locally, without a network call.

## Build and test

```sh
cd muse
npm ci
npm run build
npm test
pebble build
```

`plugin.js` is the checked-in, self-contained bundle.
The build has no dependency on a private npm registry or local checkout.

## Library and host integration

`vendor/musemeow` is a snapshot of Core Devices' `coredevices/musemeow` JS library
(base commit `ced20e4`, including the subsequent chat-list/selection implementation).
The Noise XX handshake, framing, session parsing and send protocol come from that
library. Environment adaptations are limited to host XHR/WebSocket transport,
secure randomness, Noble's X25519/AES-GCM/SHA-256 primitives, bundled protobuf
schema, fixed production endpoints, JavaScriptCore-compatible globals, and a `beforeSend`
option on `sendMain`/`sendToChat` that runs just before the message POST.
`noise.proto` is the schema source; `schema.json` is generated by `npm run build`.

Sign-in uses the host's `Pebble.webSignIn` (our-store apps, or any sideload in a debug build) to
capture the `hatch_sess` cookie; the plugin then resolves the VM ID from `muse.ai/api/session`.
The session and selected destination are stored together in `Pebble.secureStorage`. Cookies, tokens and gateway URLs are never returned from
the action or included in error messages. Disconnect removes this plugin's saved
connection; the native WebView may retain the user's Muse login.

The Muse gateway WebSocket (`hatch.metaaivm.com`) is listed under `Internet` domains.
Each connection obtains fresh admission tokens; sends are never
retried. The host gives plugins no timers and stops an action after 20 seconds, so a send
runs on an 18-second clock budget, including time waiting for another operation: with less
than 8 seconds left before the message would go out (checked again right before the POST,
after the chat lookup), it is refused as not sent. A send that
stalls after it starts can't be cut short and ends at the host limit; that, or any failure
after sending begins, is reported as uncertain delivery, so check Muse before sending again.

Like the underlying library, this supports standard Muse VMs. Confidential VM
attestation is not implemented and its challenge is rejected before any message
is sent. This is an unofficial web protocol and can change with Muse updates.

Tests cover the Node-free bundle, native/portable crypto interoperability, full
Noise handshakes and encrypted sends to main/side chats, uncertain delivery, account
changes, unavailable destinations, linked-chat filtering and redacted failures.

### Android emulator smoke test

`MuseEmulatorTest` runs the bundled settings page, native Muse sign-in launcher,
real JS engine and live network transport. It checks Main chat as the default,
changes the selected chat, refreshes the list, and verifies persistence after
restarting the plugin. The test skips unless `files/muse-emulator-auth.json` exists
in the debug app's private storage; it consumes and deletes that file at startup.
Provision an existing `musemeow` auth JSON through stdin with `adb shell run-as`
(mode 0600), never as an APK asset or command-line argument. This seeds the WebView
cookie store, so it tests session capture without automating password entry.

Build/install `:androidApp:assembleDebug` and `:androidApp:assembleDebugAndroidTest`,
then run on the selected emulator:

```sh
adb -s emulator-5554 shell am instrument -w \
  -e class coredevices.coreapp.plugins.MuseEmulatorTest \
  coredevices.coreapp.test/androidx.test.runner.AndroidJUnitRunner
```

Add `-e freshSignIn true` to start without Muse session cookies, provision the
session after the sign-in window opens, and navigate back to Muse. The test checks
that the sign-in WebView detaches and settings regain focus after session capture.

The default test only reads chats and changes plugin settings. To verify delivery,
explicitly supply a `sendMessage` instrumentation argument; that sends one real
message to Main chat, without retries.
